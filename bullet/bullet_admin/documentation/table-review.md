# Table review

[Table review](/admin/scanning/table-review/) is an optional tool to help organisers check that a team has the problem tearoffs it should have on its table during the competition. You do not need to use it to run the competition. It compares the papers you scan with the team's recorded solved problems and the category's problem allocation.

Operators can review tables at their assigned venues. Venue, country and branch administrators can also use it within their scope.

Table review does not record solved problems, change scores or mark a team as reviewed. Use [Problem scanning](/admin/documentation/problem_scanning/) for accepted solutions. The separate [Review workflow](/admin/documentation/review/) handles the final review after the competition.

## Checking a table

1. Open "Table review" in the sidebar.
2. Scan the barcode on a problem tearoff from the team's table. This selects the team.
3. Check the displayed team code and name against the table you are reviewing.
4. Scan each of the team's remaining problem tearoffs.
5. Compare the checklist with the papers on the table and resolve any discrepancies.
6. Click "Clear team" before moving to another table.

You can use a hardware barcode scanner, click "Phone scanner" to use a camera, or type the barcode into the field and click "Scan".

Use problem tearoffs, not the final summary or "no more problems" card, to select a team. The selected team stays active until you clear it, even if you reload the page.

## Reading the checklist

The checklist shows problems the system expects the team to have: from the category's first problem through the highest problem currently available to that team, excluding problems already recorded as solved.

- Green with a check means you have scanned that problem during this table check.
- Red with a cross means you have not scanned it yet. It does not necessarily mean the paper is missing.

A successful scan shows "Problem checked". Scanning the same expected problem again leaves it checked; it does not add another entry or count as a solution.

When all entries are green, you have scanned every expected problem. Also check for extra papers: an all-green checklist alone does not rule out duplicates or other teams' tearoffs.

If all issued problems have been solved, the page says that no problems should be on the table.

## Resolving discrepancies

### A problem is not expected on the table

The error names the problem and team. Check whether the problem has already been recorded as solved, whether it is beyond the team's current allocation, or whether someone gave the team the wrong tearoff.

Do not scan it on "Problem scanning" just to make the checklist agree. Record a solution only when it has been accepted according to the competition rules. If a solved-problem record is wrong, ask the person responsible for scanning or results to investigate.

### A problem remains red after checking all papers

Look for the missing tearoff and check whether the team is currently submitting it. If a solution was accepted but has not yet been recorded, the checklist can still expect that problem on the table.

Coordinate with the problem-scanning staff before replacing papers or correcting records. The checklist reflects the records available when the page loads or processes a scan; it does not update continuously on its own.

### Another team is currently selected

The page rejects scans from a different team while a team is selected. Check whether you picked up another team's paper. If you have moved to a new table, click "Clear team" and scan again.

Clearing removes the selected team and its checklist checks. It does not change any competition records.

### The barcode cannot be read or the team cannot be found

Try scanning again or enter the code manually. Check that you selected the correct competition and that the printed team number still matches the team's saved number.

If the page reports a permissions error, the tearoff belongs to a venue outside your access. Ask an organiser responsible for that venue to review it.

## Checklist state

The selected team and checked problems belong to your browser session for the selected competition. They are a temporary aid for checking one table, not a shared review record. Other organisers do not get your checklist in their own sessions.

Avoid reviewing different tables in multiple tabs of the same session: those tabs share the selected team and checks. Clear the team when you finish each table.
